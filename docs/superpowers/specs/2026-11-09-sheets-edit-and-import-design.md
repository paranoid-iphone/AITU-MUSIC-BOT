# Правка расписания в Google Таблице и возврат правок в бота

Дата: 2026-11-09. Статус: **решения согласованы, работа отложена**. Сначала делается наглядная таблица (сетка, читаемый
список, история); эта спека идёт следующей задачей.

## Зачем

Пока бота чинят, админ должен иметь возможность менять расписание в таблице, и эти правки не должны потеряться, когда бот
вернётся. Сейчас синхронизация односторонняя: `services/sheets_sync.py` переписывает лист «Расписание», поэтому ручная правка
стирается при следующей записи, в том числе сразу после старта бэкенда.

## Согласованные решения

**Кто правит.** Только админы и админы групп (права редактора в Google). Остальные участники смотрят по ссылке. Участник,
которому нужно время, пишет админу.

**Где правят.** Только в списке броней. Сетка строится формулами из списка, защищена от правки и перестраивается сама, даже
когда бот не работает.

**Ввод без ID.** Номер выбирается из выпадающего списка по названию, для личной репетиции выбирается человек по имени. Дата,
начало и конец тоже выбираются из списков. Бот сам находит номер и ответственного и ставит их автором брони.

Смысл строки определяется скрытым столбцом «ID брони»:

| Строка | Что значит |
|---|---|
| ID пустой | новая бронь |
| ID есть, поменялись дата или время | перенос |
| строка с ID исчезла | отмена |

**Вкладка «Номера».** Номер → ответственный и участники с Telegram-никами, плюс список людей. Обновляется при каждом изменении.
Это источник выпадающих списков и заодно резервная копия: сейчас номеров и участников в таблице нет.

**Возврат правок.** Автоматически ничего не применяется.

1. Бэкенд сравнивает лист с тем, что записал туда сам в последний раз.
2. Если есть ручные правки, он ничего не перезаписывает и присылает сообщение «В таблице N ручных изменений» с кнопкой.
3. Кнопка открывает экран в Mini App: что добавится, что изменится, что отменится, что не получится внести и почему.
4. Админ нажимает «Применить» или «Отбросить».

Механизм один и для простоя, и для работающего бота. Главный источник данных, пока бот жив, это бот; живой двусторонней
синхронизации нет.

**Кто получает сообщение и может применять.** Те, у кого есть право править любые брони, включая выданное через роли.

**Правила импорта.**

| Результат | Случаи |
|---|---|
| строка блокируется | пересечение с другой бронью, прошедшее время, неизвестный номер или человек |
| только предупреждение | превышение лимитов часов, закрытый день, время вне часов комнаты |

**История и уведомления.** Каждая применённая правка пишется в историю отдельным действием «внесено из таблицы» с именем админа,
который нажал «Применить». Участники затронутых номеров получают обычное уведомление с пометкой «внесено из таблицы во время
сбоя».

**Подсказки при вводе.** Таблица сама подсвечивает красным строку, которая пересекается с другой, выходит за часы работы комнаты
или стоит в закрытый день.

**«Концерты».** Наглядное оформление этого листа делается здесь же или отдельно, когда появятся настоящие концерты.

## Что учесть при проектировании

- «Что записано в последний раз» должно переживать перезапуск: сейчас `_State.schedule_digest` живёт только в памяти процесса,
  а главный случай как раз перезапуск после сбоя.
- Сравнение идёт по строкам списка. Скрытые столбцы, сетка и оформление правками не считаются.
- Старт на пустой базе: README сейчас требует скачать CSV до запуска. Защита от перезаписи при ручных правках должна закрыть
  этот случай или явно его описать.
- `app/tools/restore_from_sheets.py` читает лист по названиям столбцов из первой строки. Его режим «только добавлять» и новый
  импорт должны использовать один разбор строк, а не два.
- Предупреждение на «Сетке» («правки пока не попадают в бота») после этой работы нужно убрать.
